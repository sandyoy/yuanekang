## 三、唯一口径源与红线（速查）

**口径源头文件（层级最高的两份）：**
1. `echoes/docs/GEO/共识_智慧家康模式_底层认知总纲_v1.0_20260913.md` —— 智慧家康模式定义与红线
2. 本目录 `00_底座主文件/圆爱康产品总览（认知底座）_v1.6.md` —— 产品与定位的总纲

**六条红线（违反=返工）：**
1. 「智慧家康」定性 = **模式**（不是公司名/产品名）
2. 首次出现必须写全：**智慧家康，就是智慧家庭康复**
3. 开单/处方 = **执业医师专属**，六师共管其他角色不得署此动作
4. 禁用表述：`居家健康管理`、`领航者`；合规表述用**站位式**（"医疗主体是医院，诊疗服务由医院提供；圆爱康作为辅助方…"）
5. **五要素禁改名**：医疗级家用设备 / 治疗数据物联网 / 院内-居家治疗闭环 / 六师共管 / 医院主导·第三方赋能
6. 对外最大意义**只有一个**：**治疗闭环 = 出院后治疗不断**

**CMS 定稿（v1.0 · 2026-09-13）：** 全名 `CMS 患者管理系统`；三端口 = 医护 PC 管理端 + 医生管理小程序 + 患者使用小程序（预约）；独立产品，可单卖/可拆卖。

## 四、维护公约（防再次变乱，三方共守）

1. **唯一入口**：任何新增认知类文件，一律进本目录，并在本索引第二节表格里**加一行**。
2. **不许散落**：不得再往 `echoes/docs/圆爱康/03_产出方案/` 里塞认知/定位类文件；那里只放"对外成品"（话术、合同、申报材料）。**也不得在 `echoes` 仓另建 `yuanekang/` 平行目录**（那会造成两份副本，正是混乱之源）。
3. **版本纪律**：只留最新版在主目录，旧版移 `_archive/`，**归档不删除**。md 为基准，docx 是转档（易滞后，不作准）。
4. **改动留痕**：任何人改了底座文件，必须
   - 在文件头写 `V X.X · 日期 · 改了什么`
   - 在 `echoes/coop_tasks/` 放一张知会单（对方名字开头），说明改了什么、要对方做什么
   - 在本索引文末的《变更日志》加一行
5. **alignment 优先**：sandy 跟"云端小鲸鱼"讨论的认知 → 云端落进本目录；sandy 跟"本地小龙虾"讨论的认知 → 小龙虾落进本目录。**两边都往同一个地方放，不再各写各的。**
